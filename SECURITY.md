# Security Policy — ORAKZAI GROUP

## Supported Versions

| Version | Status | Security Updates |
|---------|--------|-----------------|
| Latest (main) | ✅ Active | Yes |
| Previous releases | ⚠️ Deprecated | Critical only |

## Reporting a Vulnerability

The ORAKZAI GROUP takes security seriously across all platforms —
blockchain, AI, real estate, and e-commerce infrastructure.

### Private Disclosure

**DO NOT** open a public issue for security vulnerabilities.

Report security issues privately via:

- **Email:** security@orakzai.com
- **LinkedIn:** [linkedin.com/in/faisalorakzaii](https://linkedin.com/in/faisalorakzaii) (DM)
- **GitHub Security Advisory:** Use the "Report a vulnerability" button on this repo

### What to Include

1. Description of the vulnerability
2. Steps to reproduce (proof of concept)
3. Potential impact assessment
4. Suggested remediation (optional)

### Response Timeline

| Stage | Timeframe |
|-------|-----------|
| Initial acknowledgment | Within 48 hours |
| Vulnerability assessment | Within 7 days |
| Patch development | Within 30 days (critical: 72 hours) |
| Public disclosure | After patch is deployed |

## Security Standards

- **Smart Contracts**: Audited before mainnet deployment
- **API Keys**: Never committed; managed via environment secrets
- **Authentication**: JWT + Supabase RLS policies
- **Data**: Encrypted at rest and in transit (TLS 1.3)
- **Blockchain**: Multi-sig for treasury operations

## Bug Bounty

We appreciate responsible disclosure. Reporters of verified vulnerabilities
will be acknowledged in our security hall of fame and may receive recognition
from the ORAKZAI GROUP team.
